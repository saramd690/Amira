# توثيق نظام ملف المرشح والسيرة الذاتية

## قاعدة البيانات
- `candidate_profiles`: ملف المرشح الأساسي، ويرتبط `user_id` مباشرةً بـ `auth.users.id`، ويحتوي الجامعة والكلية والتخصص ونسبة الاكتمال وحالة التفرغ.
- `educations`: المؤهلات والمؤسسات والتواريخ.
- `experiences`: الوظائف والخبرات العملية.
- `languages`: اللغات ومستوى الإتقان.
- `certificates`: الشهادات والجهات المانحة وتواريخ الصلاحية.
- `projects`: المشاريع وروابطها.
- `cv_versions`: سجل نسخ السيرة الذاتية، مع رقم الإصدار ومسار الملف والنوع والحجم والنسخة النشطة.
- `candidate_privacy_settings`: مستوى ظهور الملف وخيارات إظهار بيانات الاتصال وتنزيل CV.
- `candidate_availability_history`: سجل تغييرات التفرغ.

كل جدول مفعّل عليه RLS. تسمح السياسات للمستخدم المصادق عليه بإدارة الصفوف التي يملكها فقط، بينما سجل التفرغ قابل للقراءة من صاحبه ويُكتب إليه بواسطة Trigger داخلي.

## اكتمال الملف
تُحسب النسبة تلقائيًا عند تحديث البيانات الأساسية أو سجلات التعليم والخبرة واللغات والشهادات والمشاريع ونسخ CV. الأوزان: البيانات الشخصية 20%، البيانات الأكاديمية الأساسية 20%، التعليم 15%، الخبرة 15%، اللغات 10%، الشهادات 5%، المشاريع 5%، ورفع CV 10%.

## الحسابات وتسجيل الدخول
يدعم التطبيق إنشاء حساب مرشح، تأكيد البريد الإلكتروني عبر `/auth/callback`، تسجيل الدخول، طلب إعادة تعيين كلمة المرور، تعيين كلمة مرور جديدة، وتسجيل الخروج. عند إنشاء حساب جديد يُنشأ ملف المرشح وإعدادات الخصوصية تلقائيًا، كما تُنشأ السجلات الافتراضية للمستخدمين السابقين عند تطبيق ترقية قاعدة البيانات.

## تخزين السيرة الذاتية
اسم Bucket هو `candidate-cvs` وهو خاص. حد الرفع 10 ميجابايت، والأنواع المقبولة PDF وDOCX. يجب أن يبدأ مسار الملف بمعرّف المستخدم، مثل `auth-user-uuid/file-name.pdf`. تسمح سياسات `storage.objects` بالرفع والقراءة والتحديث والحذف داخل مجلد صاحب الملف فقط. المعاينة تُنشئ رابطًا موقعًا صالحًا لمدة دقيقة، ولا يُخزّن رابط عام دائم. ملفات PDF تُعرض داخل المنصة، وملفات DOCX تُعرض كنص مستخرج آمن، مع إمكانية تنزيل النسخة الأصلية.

## واجهات API
- الملف الشخصي: `GET/PATCH /api/v1/candidate/profile`.
- التعليم والخبرة واللغات والشهادات والمشاريع: `GET/POST /api/v1/candidate/{education|experience|languages|certificates|projects}`، و`PATCH/DELETE /api/v1/candidate/:resource/:id`.
- CV: `POST/GET /api/v1/candidate/cv` و`GET /api/v1/candidate/cv/:id` لإنشاء رابط معاينة مؤقت، و`GET /api/v1/candidate/cv/:id/preview` لمعاينة PDF وقراءة نص DOCX. و`PATCH /api/v1/candidate/cv/:id` لتفعيل نسخة سابقة، و`DELETE` لحذف نسخة مع تفعيل أحدث نسخة تلقائيًا عند حذف النشطة.
- التفرغ: `PATCH /api/v1/candidate/availability`.
- الخصوصية: `GET/PATCH /api/v1/candidate/privacy`.

تتحقق المسارات من جلسة Supabase باستخدام `auth.getUser()` وتستخدم `user_id` الخاص بالجلسة، ولا تقبل معرف المالك من جسم الطلب. تظل RLS طبقة الحماية الأساسية في قاعدة البيانات.

## ربط التطبيق بـ Supabase
ضع `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` في `.env.local`. أضف `http://localhost:3000/auth/callback` وعنوان الإنتاج `https://YOUR_DOMAIN/auth/callback` إلى قائمة Redirect URLs المسموح بها في Supabase Auth، واضبط Site URL على عنوان التطبيق المنشور. يجب أن تشير قوالب تأكيد البريد واستعادة كلمة المرور إلى مسار `/auth/callback`. لا تضع `service_role` أو Secret Key في الواجهة أو أي متغير يبدأ بـ `NEXT_PUBLIC_`. ينشئ `src/lib/supabase/server.ts` عميل الخادم مع Cookies الجلسة.

## حدود معروفة
إعدادات الخصوصية تحفظ اختيارات المرشح، لكن واجهة وصول الشركات لم تُفعّل بعد. يجب تعريف أدوار الشركات ومسؤولي التوظيف وموافقة المرشح وسياسات القراءة المناسبة قبل نشر أي بيانات لهم. بيانات المهارات والطلبات والترشيحات والمقابلات في لوحة التحكم بيانات Mock وليست بيانات حقيقية.
